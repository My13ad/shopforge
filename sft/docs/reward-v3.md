# Reward v3

Reward v3 根据 Agent 实际购买的商品和规格计算终局奖励。评分使用环境中的商品、价格和需求证据，无需调用额外模型作为裁判。

## 需求与硬门槛

开始交互前，环境将任务要求和目标商品元数据转换为固定评分特征，包括品类、预算上限、品牌、型号、核心功能及颜色、尺码、容量、套餐等规格。Agent 的后续操作不会改变这些要求。

购买必须同时满足品类和预算。品类错误或所选规格价格超过预算时，终局为 `wrong_purchase`，奖励 `-0.85`。如果环境缺少核对硬门槛所需的证据，则标记 `reward_unverifiable`、`reward_valid=false`，数值记为 `0.0`。

## 偏好评分

仅对任务中出现的维度计分：

| 维度 | 权重 |
|---|---:|
| 品牌 | 0.35 |
| 型号 | 0.25 |
| 核心功能 | 0.25 |
| 关键规格 | 0.15 |

```text
S = Σ(weight_i × score_i) / Σ(active weight_i)
```

证据覆盖率按同样的有效维度权重计算。完全满足要求需要匹配分和证据覆盖率均为 1.0。

## 终局奖励

| 结果 | 奖励 |
|---|---:|
| 目标商品，全部要求满足 | `1.00` |
| 其他商品，全部要求满足 | `0.55` |
| 部分符合的替代商品 | `min(0.25, -0.30 + 0.55 × S)` |
| 充分搜索后合理停止 | `-0.15` |
| 搜索不足便停止 | `-0.35` |
| 达到 35 步上限 | `-0.50` |
| 重复或无进展循环 | `-0.65` |
| 品类错误或超预算 | `-0.85` |
| 关键证据缺失 | `0.00`，无效奖励 |

命中目标商品的终局称为 `gold_purchase`。其他商品通过全部要求时称为 `valid_alternative_purchase`，也获得正奖励。README 中的严格成功率只统计前者，因此严格成功率与平均奖励反映不同信息。

## 停止与循环

合理停止要求 Agent 至少查看两组有效搜索结果、打开两个候选，并且没有已知可接受商品。已知可接受商品需要通过硬门槛，偏好匹配至少为 0.70，证据覆盖率至少为 0.75。

环境在连续两次完全重复、连续四步没有新证据或总步数达到 35 时终止。搜索结果、打开新商品、详情子页、规格选择和约束检查都可构成进展证据。
